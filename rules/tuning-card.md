【autoPID 调参卡 · 人工设定】涉及 PID 调参时按这张卡来，不要凭直觉加大增益。

当前关注度：Kp 抖动 {{kpOsc}} · Ki 摆动 {{kiOsc}} · 响应速度 {{speed}} · 稳态均值 {{steady}}（0~100，越大越在意）

取舍顺序：
- 稳态追不上，先加 Ki（增量式的稳态误差靠 Ki 消，Kp 加多少都没用）
- 追得上但响应慢，再动 Kp，一档一档来
- 只有超调明显才动 Kd，动大了会放大测量噪声

红线（不受上面权重影响）：
- 先 STOP 再改参数；改完 RESET 再 START
- 单步放大不超过 2 倍；要试探极限值必须先问人，并说清可能出现什么现象
- 能动起来之前先架起来空转；出现异响、发热、速度长时间贴 0 立刻停
- 没测过的参数不许说"应该没问题"

汇报只给三段：试了什么（参数 + 采集窗口）／数据怎么说（稳态、上升、抖动、摆动 + 有没有失效）／下一步建议（改谁、改到多少、为什么）。

**每一轮实验结束都必须出图**（硬规则，和上面红线同级）：
- 用 `autopid_plot` 把这一轮单独画出来，参数带 `width: 3200`、`height: 520`，横轴拉长才看得出细节
- 汇报里必须给出图的文件路径
- 数据已经停了（`autopid_status` 里 newest_age 很大）时**不要用 `window`**，改用 `start` / `end` 指定那一轮的时间戳，否则只会画到最后一小段
- 想让人直接看到，就用 Markdown 图片语法贴进回复（`![说明](路径)`）—— 这条路不污染会话；**绝对不要把图片塞进工具返回值**

**判断抖动必须用原始采样，不许先做滑动平均**（硬规则，和上面同级）：
- 滑动平均会把 30~70 Hz 的抖动直接抹平 → 数字看着漂亮、车上却在抖（2026-11-02 我就这么漏判过一次，把 Kp=90 说成最优，实际抖动比 Kp=60 大五成）
- 算抖动用的三个量，全部基于**未平滑**的数据取稳态段：**峰峰值**、**逐点平均跳变**（相邻两点的差取绝对值再平均）、**方向翻转频率**（相邻差值的正负变化次数 ÷ 时长）
- 平滑**只能**用来看趋势和算上升时间（到 63% / 90%），不许用来说"抖不抖"
- 报告里要写清"这个抖动是用原始数据算的"，别让人再猜一遍

**角度环（转向/循迹）用四个固定指标判断，别现场发明**（硬规则，详细算法见 `tuning-rules.md` 第七节）：
- 需要的三列：`Position_Error`（必须在中断清零前存成 last_err，直接打印会恒为 0）、`gyro_z`、`lightsum`（0 = 脱线）
- 指标一 **脱线率** = lightsum==0 的帧占比；< 5% 健康 / 5~20% 勉强 / > 20% 有问题
- 指标二 **摆幅 q90** = |Position_Error| 的第 90 百分位；**不许用峰峰值**（一个尖峰就能毁掉极差）；< 10 / 10~20 / > 20
- 指标三 **加权收敛率 R** = Σ(e·ω) / Σ|e·ω|；**负 = 在纠偏，正 = 在发散**；< −0.6 健康 / −0.6~−0.3 勉强 / > −0.3 有问题。尖峰会被时间平均掉，所以能容忍"一瞬间放大"
- 指标四 **尖峰恢复** = 对每个 |e|>20 的尖峰，量回到 |e|<5 的中位耗时；< 50ms 好 / 50~150ms 正常 / > 200ms 或永不归零 = 阻尼不足
- 决策：R 对但 q90 大 → 加 p1；R 在发散 → 先查符号别加增益；尖峰收不回来 → 加 |g|（gkd 取负）；均值一直单向 → 查机械/左右不对称，别拿增益硬调
