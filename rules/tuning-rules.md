# dsh-autoPID 调参规则（内置规则文件）

这份文件是**给 AI 看的操作手册**，不是给单片机看的。插件启动时从本目录读取，
`autopid_tuning_rules` 工具会把它连同当前权重一起返回。
**改这份文件不用重启 DSH，但改完最好重新调用一次 `autopid_tuning_rules` 确认读到的是新版。**

---

## 一、四个权重（设置页里是滑块，0~100）

| 键 | 含义 | 当前值 |
|---|---|---|
| `tuneKpOsc` | 对 **Kp 引起的高频抖动** 的关注度 | {{kpOsc}} |
| `tuneKiOsc` | 对 **Ki 引起的低频摆动 / 超调** 的关注度 | {{kiOsc}} |
| `tuneSpeed` | 对 **响应速度（上升时间）** 的关注度 | {{speed}} |
| `tuneSteady` | 对 **稳态均值 / 稳态误差** 的关注度 | {{steady}} |

四个权重是**打分权重**，不是互相排斥的档位。每个候选参数组合都按下式算一个分：

```
score = 100
      - tuneSteady × steadyErr%      / 100
      - tuneSpeed  × riseTime_ms     / 100
      - tuneKpOsc  × rippleRatio     / 100
      - tuneKiOsc  × swingRatio      / 100
```

其中

- `steadyErr%`：稳态均值相对目标的百分比误差（取绝对值）
- `riseTime_ms`：上升时间，优先用到 63% 的时间，算不出就用 30%~70% 段折算
- `rippleRatio`：**稳态段高频抖动** —— 平滑后尾段峰峰值 ÷ 目标值 × 100
- `swingRatio`：**低频摆动/超调** —— 超调百分比 + 稳态段缓慢漂移幅度（÷ 目标 × 100）

> 权重为 0 表示"这一项完全不看"，100 表示"这一项最要紧"。
> **分数只是排序工具，不能替代物理约束** —— 见第五节。

## 二、必须先知道的机理（踩过坑，别再犯）

1. **这是增量式 PID**：`output += Kp·(e−e_prev) + Ki·e + …`
   - 匀速段 `e−e_prev ≈ 0` → **Kp 对稳态误差几乎没作用**
   - **稳态误差靠 Ki 消**，Kp 只影响动态（跟得快不快、抖不抖）
   - 所以「追不上目标」先去加 Ki，别急着加倍 Kp
2. **上位机发的系数还要乘缩放常数**（本仓库默认 `PIDInc_Kp=1.0 / Ki=0.03 / Kd=0.3`）：
   发 `SET 20 30 0` 实际是 Kp=20、Ki=0.9、Kd=0。
   报结果时**两个数都给**（下发的数字 + 实际生效值），否则下次没人算得回来。
3. **量化噪声跟真实振荡要分清，但别用平滑去分**（2026-11-02 修正了旧口径）：
   速度通常是整数计数，尾段峰峰差 **1~2 个计数**属于量化噪声；一旦峰峰明显超过这个量级（比如达到目标的 10%~20%），那就是真抖动，不能拿"整数化"糊过去。
   **判抖动用原始数据**（峰峰 / 逐点平均跳变 / 方向翻转频率）；**平滑只用来算上升时间和看趋势** —— 旧版这里写"判断振荡前必须先做 30ms 滑动平均"，那条是错的（它会正好把要找的东西抹平），已作废。
4. **目标自己会变**（示例固件里每 3 秒换一次目标）——这是刻意留的激励信号，
   按"目标变化"切段分析，不要当成噪声或故障。

## 三、调参流程（照这个顺序，别跳）

**第 0 步：安全前置**

- 每轮实验前先 `STOP`，改完参数再 `RESET`，最后 `START`
- 拿不准就先把车架起来空转
- **单步放大不超过 2 倍**；想试极限值必须**先问操作者**，并说明可能出现的现象

**第 1 步：先定 Ki（稳态），Kp 给一个保守值**

- 从 `Kp=20 / Ki=30 / Kd=0` 这一组起步（智能车实测很稳）
- 看 `steadyErr%`：还差得远就加 Ki，一步 ×2；出现低频摆动就往回退

**第 2 步：再调 Kp（动态）**

- 在 Ki 固定的情况下把 Kp 往上走：20 → 40 → 80，**每步只动一档**
- 关注 `riseTime_ms`（变小 = 变快）和 `rippleRatio`（变大 = 开始抖）
- 出现"更快但逼近时来回蹭"（到 90% 反而变慢）就是**过头了**，退回上一档

**第 3 步：最后看 Kd（抑制超调）**

- 只有 `swingRatio` 明显时才加 Kd，且从小值开始
- Kd 太大会放大测量噪声 → `rippleRatio` 飙升，这时宁可退回

**第 4 步：按权重收口**

- 把历次实验的记录拿出来，用第一节的公式算分，取分最高的那组
- **但要同时报告"稳健性"**：如果最高分那组离失效边界只差一档，建议选保守的那组

## 四、每轮实验必须记录（少一项就没法比较）

| 项 | 例 |
|---|---|
| 下发参数 | `SET 20 30 0`（实际 Kp=20 / Ki=0.9 / Kd=0） |
| 采集窗口 | `since=1793542616`，约 20 秒 |
| 稳态误差 | 左 -0.8% / 右 -1.1% |
| 上升时间 | 到 63% 用 46 ms |
| 高频抖动 | 尾段峰峰 2.2 计数 |
| 低频摆动/超调 | 超调 5.6%，无缓慢漂移 |
| 是否失效 | 否 |

**失效的判据**（任一条成立就算"这一档不能用"）：
速度长时间贴 0、目标追不到一半、纹波峰峰超过目标的 15%、驱动明显发热或有异响。

## 五、硬性红线（权重再高也不能越）

1. **不允许在真机上一次把增益放大超过 2 倍**（哪怕是为了找边界）
2. **不允许在带载、贴地、有人的场合做极限实验**；能空转就空转
3. **出现异常立刻 STOP**，先把参数退回上一组安全值，再解释
4. **没测过的参数不许说"应该没问题"** —— 没数据就说没数据
5. 权重只决定"取舍方向"，**不改变安全约束**：`tuneSpeed=100` 也不代表可以越界冲刺
6. **每一轮实验结束都必须出图**（和上面几条同级，不是可选项）：
   - 用 `autopid_plot` 单独画这一轮，**`width: 3200`、`height: 520`** —— 横轴拉长到才看得出逼近段和目标附近的细节
   - 汇报里必须写出图的文件路径
   - 数据已停（`autopid_status` 的 `newest_age` 很大）时**别用 `window`**，用 `start`/`end` 指向那一轮的起止时间戳，否则只画到最后一小段
   - 要让人在对话里直接看，就用 Markdown 图片语法贴（`![说明](路径)`）；**绝不要把图片塞进工具返回值**（会永久毒死会话）
7. **判断抖动必须用原始采样，不许先做滑动平均**（2026-11-02 用真实教训换来的）：
   - 平滑会把 30~70 Hz 的抖动直接抹掉 → 数字漂亮但车上在抖。上次我就这么把 `Kp=90` 判成最优，实际它的平均跳变比 `Kp=60` 大五成、`Kp=135` 在目标 100 段峰峰到 61%
   - 算抖动只用这三个量，全部基于**未平滑**数据取稳态段：**峰峰值**（占目标百分比）、**逐点平均跳变**（相邻两点差取绝对值再平均）、**方向翻转频率**（相邻差的正负变化次数 ÷ 时长）
   - 平滑**只允许**用来看趋势、算上升时间（到 63% / 90%），**不许**用来判断抖不抖
   - 汇报里必须写一句"抖动基于原始数据"，否则读者没法判断可信度

## 六、给操作者的汇报格式（三段，别写小作文）

1. **这轮试了什么**：参数 + 窗口
2. **数据怎么说**：稳态/上升/抖动/摆动 四个数，外加"有没有失效"
3. **建议下一步**：改哪个参数、改到多少、为什么（引用权重）

## 七、角度环（转向 / 循迹）的质量判据 —— 照这个算，别现场发明

速度环有"目标值"可比，角度环没有，所以用**四个固定指标**。全部基于**原始采样**（不平滑），窗口取"轮子在转"的那些帧。

### 7.1 需要的三列数据

| 列 | 含义 | 没有它就没法算 |
|---|---|---|
| `Position_Error` | 线偏差（必须是在中断清零**之前**存下的 `last_err`，直接打印会恒为 0） | 全部指标 |
| `gyro_z` | 转向角速度（deg/s） | 收敛率、阻尼 |
| `lightsum` | 这一拍看到几路黑线；**0 = 脱线** | 脱线率 |

### 7.2 四个指标（算法照抄）

```
① 脱线率    = (lightsum == 0 的帧数) / (总帧数) × 100%
② 摆幅 q90  = 所有 |Position_Error| 排序后的第 90 百分位
③ 加权收敛率 R = Σ(e × ω) / Σ|e × ω|          （e = Position_Error, ω = gyro_z）
④ 尖峰恢复  = 对每个 |e| > 20 的尖峰，量它之后 e 回到 |e| < 5 用了多少毫秒；
              取这些耗时的**中位数**（不是平均，避免个别收不回来的尖峰带偏）
```

### 7.3 为什么用这些（不是随便挑的）

- **不用峰峰值**：`Position_Error` 会有一瞬间放大，一个尖峰就能把极差毁掉（实测同一段数据峰峰 14%，标准差只有 2.5%）。**摆幅一律用分位数**。
- **收敛率 R 用加权、不用符号占比**：每个时刻的贡献被 `|e|` 加权 → 尖峰权重大但持续短，正常帧数量多 → 尖峰自动被时间平均掉，整体看的是"这段时间到底在纠偏还是在发散"。
- **收敛率的物理含义**：`e × ω` 约等于 `−误差²` 变化率的一半（差一个几何系数）→ **负 = 误差在缩小（纠偏），正 = 误差在变大（发散）**。
- **恢复时间专治"尖峰很快归零"**：尖峰本身不可怕，**回不回得来**才可怕。

### 7.4 判据表（直接用）

| 指标 | 健康 | 勉强 | 有问题 |
|---|---|---|---|
| 脱线率 | < 5% | 5~20% | > 20% |
| 摆幅 q90 | < 10 | 10~20 | > 20 |
| 加权收敛率 R | < −0.6 | −0.6 ~ −0.3 | > −0.3（在发散） |
| 尖峰恢复（中位数） | < 50 ms | 50~150 ms | > 200 ms 或有尖峰永不归零 |

### 7.5 决策表（指标 → 改哪个参数）

| 现象 | 判断 | 动作 |
|---|---|---|
| R < −0.6 且 q90 < 10 | 健康 | 收工，别再动 |
| R < −0.6 但 q90 > 20 | 方向对、力度不够 | **加 p1**（一次 ≤ 1.5 倍） |
| R > −0.3、脱线率高 | 在放大误差（相位/符号问题） | **先查符号与陀螺项正负**，别加增益 |
| 尖峰恢复 > 200 ms 或收不回来 | 阻尼不足 | **加 |g|**（gkd 取负，一次 ≤ 2 倍） |
| 摆幅来回过零频繁（画龙） | 增益太大或阻尼不足 | 先减 p1，再考虑加 |g| |
| 稳态误差一直单向（均值不接近 0） | 结构性偏差（车装歪 / 左右不对称） | 查机械与左右轮系数，**别用增益硬调** |

### 7.6 两个必须注意的坑

1. **同一拍取值**：`Position_Error` 若用上一拍的 `last_err`、`gyro_z` 用当前拍，会差 1 ms —— 对符号判断影响极小，但要精确就都取同一拍。
2. **不要用"最大偏差"当指标**：`Position_Error` 在多路光电池同时看到线时会自然变得很大（单路边沿约 ±11，多路可到 ±36），那是正常的几何结果，不是失控。**看恢复时间与收敛率，不看峰值。**

### 7.7 汇报格式（角度环也只用三段）

1. 试了什么：`SET kp ki kd p1 p2 d g`（**实际生效值 = 下发值 × 缩放常数，两个都要给**）
2. 数据怎么说：脱线率 / q90 / R / 尖峰恢复，四个数
3. 建议下一步：改哪个、改到多少、为什么（引用上面 7.5 的哪一行）
